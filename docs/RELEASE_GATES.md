# Owner approval and deployment gates

**G0 — Intake:** confirmed scope, source material, attribution, no duplication or nonpublic material; work may be drafted on a feature branch.

**G1 — Technical/content review:** PR checks for accessibility, source grades, false affiliation, privacy/security, licensing, and broken links. Research figures require scientific/metric review; proposed design concepts require appropriate external professional input.

**G2 — Owner merge approval:** the repository owner must explicitly approve merging the reviewed changes. Passing checks is not equivalent to approval.

**G3 — Public release approval:** before enabling GitHub Pages, publishing a site, attaching a live domain, collecting user data, or issuing public campaign claims, obtain specific approval. Verify domain ownership, DNS, accessibility, mobile behavior, privacy, consent for forms/analytics, and media rights.

**G4 — Site-/field-specific work:** development visuals and research fieldwork require separately documented permissions, site facts, stakeholder/partner input, and professional review. No public depiction of authorization before it exists.

This initial PR is **G0 only**. It must remain draft/unmerged pending G1–G2; no deployment is requested.
