# Visualization and animation candidates

**Status: evaluated candidates, not installed packages or approved public renderings.** The [working tool register](https://docs.google.com/document/d/1qtskm6eZA2hbxu962smlFWufx4KrNRlk6I9TNIUYYog/edit) lists 18 upstream repositories. This file records ORB-specific proposed uses rather than claiming that all are needed.

| Tier | Tool | Candidate use |
|---|---|---|
| Initial pilot | [Motion Canvas](https://github.com/motion-canvas/motion-canvas) | Source-linked system/process diagrams |
| Initial pilot | [Remotion skills](https://github.com/remotion-dev/skills) | Narrated explainers and source-dated briefs |
| Initial pilot | [Two.js](https://github.com/jonobr1/two.js) | Lightweight 2D figures |
| Conditional | [Manim](https://github.com/ManimCommunity/manim) | Quantitative explanations |
| Conditional | [Motion](https://github.com/motiondivision/motion) / [Konva](https://github.com/konvajs/konva) | Future interactive dashboards |
| Later / partner reviewed | [Blender](https://github.com/blender/blender) and [Three.js](https://github.com/mrdoob/three.js) | Conceptual Future Shotgun and district studies |
| Optional export | [Lottie Web](https://github.com/airbnb/lottie-web) | Lightweight animated icons |

No dependency should be adopted without a quality baseline, license/security/accessibility/mobile-performance check and owner approval. Avoid adopting competing 3D engines without a documented need.

Every scene/figure must include its model version, data/source IDs, date and **fact / assumption / illustrative scenario / concept** classification. Never depict ORB as controlling a site, certifying suppliers, or holding a government partnership.

Start with **V009 asset inventory**, **V001 supplier-readiness diagram**, and **V002 Value Pool 0 architecture** from the [visual upgrade backlog](https://docs.google.com/spreadsheets/d/1fsWe2buAgQtcD2d-XKzdXNRufc5JL-ocWCpcoBoj8gs/edit). Nothing in this folder establishes engineering feasibility.
